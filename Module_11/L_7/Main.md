### Задание 1

Опишите основные преимущества использования масштабирования методами:

- активный master-сервер и пассивный репликационный slave-сервер; 
- master-сервер и несколько slave-серверов;


*Дайте ответ в свободной форме.*

#### Решение  

1. Активный master-сервер и пассивный репликационный slave-сервер:  

Эта конфигурация (часто называемая Master-Standby или классическим Failover-кластером) ориентирована не на распределение текущей нагрузки, а на отказоустойчивость, надежность и безопасность. Пассивный слейв не принимает запросы от пользователей, а лишь зеркалирует мастер. (В случае отказа мастер ноды, слэйв становится мастером до момента включения/возвращения мастер ноды)   

Основные преимущества:  
--Отказоустойчивость (High Availability) и быстрое восстановление  
--Безопасное создание бэкапов без потери производительности  
--Минимальные риски повреждения данных  
--Простота обслуживания  

2. Master-сервер и несколько slave-серверов:  

Эта схема (классический Read-Scaling) создана для горизонтального масштабирования производительности высоконагруженных систем, где количество чтений данных значительно превышает количество записей (например, интернет-магазины, соцсети, новостные порталы). Все операции записи (добавление, изменение, удаление) идут на master, а все операции чтения (просмотр каталога, поиск, генерация отчетов) распределяются между слейвами.  

Основные преимущества:  
--Колоссальное увеличение производительности на чтение (за счет распределения нагрузки)  
--Эффективная аналитика и Big Data  
--Гибкое и дешевое масштабирование  
--Повышенная живучесть системы на чтение

### Задание 2


Разработайте план для выполнения горизонтального и вертикального шаринга базы данных. База данных состоит из трёх таблиц: 

- пользователи, 
- книги, 
- магазины (столбцы произвольно). 

Опишите принципы построения системы и их разграничение или разбивку между базами данных.

*Пришлите блоксхему, где и что будет располагаться. Опишите, в каких режимах будут работать сервера.* 

#### Решение

Исходные данные:  
  
Таблица users (Пользователи)  
Эта таблица содержит персональные данные клиентов. Из-за потенциально огромного количества пользователей она подвергается горизонтальному шардингу.  
  
|Имя колонки|Тип данных|Ограничения|Описание и роль в архитектуре|
|:---:|:---:|:---|:---|
|user_id|BIGINT|PRIMARY KEY, AUTO_INCREMENT|Уникальный идентификатор пользователя. Используется как Shard Key (ключ шардирования) для распределения строк по серверам.|
|first_name|VARCHAR(50)|NOT NULL|Имя пользователя.|
|last_name|VARCHAR(50)|NOT NULL|Фамилия пользователя.|
|email|VARCHAR(100)|NOT NULL, UNIQUE|Электронная почта. Используется для авторизации. Должна быть уникальной в рамках всей системы (проверка уникальности переносится на уровень приложения).|
|registration_date|TIMESTAMP|NOT NULL, DEFAULT NOW()|Дата и время регистрации аккаунта. Может использоваться для временного (Range-based) шардирования.|


Таблица books (Книги)  
Таблица представляет собой каталог товаров. Из-за большого ассортимента и частых поисковых запросов она разделена вертикально от пользователей и шардируется горизонтально.  

|Имя колонки|Тип данных|Ограничения|Описание и роль в архитектуре|
|:---:|:---:|:---|:---|
|book_id|BIGINT|PRIMARY KEY, AUTO_INCREMENT|Уникальный идентификатор книги. Используется как Shard Key для хэш-шардирования каталога.|
|title|VARCHAR(255)|NOT NULL|Название книги.|
|author|VARCHAR(150)|NOT NULL|Автор или соавторы произведения.|
|isbn|VARCHAR(13)|UNIQUE|Международный стандартный книжный номер (13 цифр). Позволяет однозначно идентифицировать издание.|
|price|DECIMAL(10,2)|NOT NULL, CHECK (price >= 0)|Стоимость книги. Тип DECIMAL исключает ошибки округления, свойственные числам с плавающей точкой.|
|stock_quantity|INTNOT NULL, DEFAULT 0|Текущий остаток книги на складах/в магазинах. Самая часто обновляемая колонка (UPDATE).|
